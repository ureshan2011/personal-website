Two statements, one little safety net

UPDATE changes rows; DELETE removes them. Both quietly hit every row in the table unless you add a WHERE clause to say which rows you mean. Here’s the difference at a glance.

AspectUPDATEDELETE
What it doesChanges values in rowsRemoves rows entirely
Needs WHERE?Yes — or every row changesYes — or every row is deleted
Keyword to set valuesSET column = value— (no SET)
Worst-case mistakeAll rows overwrittenWhole table emptied
Safety habitSELECT first, then UPDATESELECT first, then DELETE

Without WHERE

DELETE FROM students;
UPDATE students SET grade = 'F';

Hits every single row. Everyone fails. Everyone is deleted.

With WHERE

DELETE FROM students WHERE id = 3;
UPDATE students SET grade = 'F'
 WHERE id = 3;

Only the rows you target change. Precise, predictable, sane.

Three habits that save your data

Do these every time and you’ll never empty a table by accident.

SELECT before you change

Run a SELECT with the same WHERE first. If it returns the rows you expect, swap SELECT for UPDATE or DELETE.

Beware WHERE 1=1

A condition that is always true affects every row — the same as having no WHERE at all.

Wrap it in a transaction

BEGIN, run your change, check it, then COMMIT if happy or ROLLBACK to undo. Your future self says thanks.
